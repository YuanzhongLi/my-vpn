# インフラ構成比較: EC2 vs ECS (Fargate) vs Lightsail

## 概要

VPNサーバーの実行環境として、AWS上の主要な選択肢を比較し推奨を決定する。
前提として、サーバーは常時起動ではなく必要時のみ起動し、コストを最適化する。

## 比較対象

1. **EC2** - 仮想マシン（最も柔軟）
2. **ECS on Fargate** - サーバーレスコンテナ
3. **ECS on EC2** - EC2上でコンテナを実行
4. **Lightsail** - シンプルなVPS（参考）

## 詳細比較

### 1. EC2 (Elastic Compute Cloud)

#### 構成
- t3.micro または t3.nano インスタンス
- Amazon Linux 2023 or Ubuntu 24.04
- Elastic IP割り当て
- WireGuardをインストール・設定

#### メリット
- **完全な制御**: OS/カーネルレベルのアクセス、カーネルモジュール(WireGuard)の利用可能
- **Elastic IP**: 固定IPを直接割り当て可能
- **シンプル**: VPN構築の情報・事例が最も豊富
- **起動/停止が容易**: AWS CLI `aws ec2 start-instances` / `stop-instances`
- **停止時コスト**: インスタンス停止中はコンピューティング費用なし（EBS/EIPのみ）

#### デメリット
- **起動時間**: 停止→起動に30秒〜1分程度
- **パッチ管理**: OS/パッケージの更新は自分で行う必要あり
- **スケーリング**: 手動での対応が基本（Auto Scaling Groupで自動化は可能）

#### コスト見積もり（東京リージョン）

| リソース | 仕様 | 月額（USD） |
|---------|------|------------|
| EC2 (t3.micro) | 1日8時間 × 30日 | ~$2.50 |
| EC2 (t3.nano) | 1日8時間 × 30日 | ~$1.25 |
| EBS (gp3) | 8GB | ~$0.76 |
| Elastic IP | 使用中は無料、停止中は課金 | ~$3.65 (停止中) |
| データ転送 | 100GB/月 | ~$11.40 |
| **合計 (t3.nano)** | | **~$17/月** |

※ 2024年2月よりElastic IPは使用中でもアドレスに課金される（$0.005/時間）。ただしEC2に紐付けて起動中は無料。

### 2. ECS on Fargate

#### 構成
- WireGuardをDockerコンテナ化
- Fargate上でタスクとして実行
- NLB (Network Load Balancer) + Elastic IP

#### メリット
- **サーバーレス**: EC2インスタンスの管理不要
- **起動/停止**: タスク数を0↔1で制御
- **コンテナ化**: イメージで環境を完全に再現可能
- **スケーリング**: タスク数の増減で対応可能

#### デメリット
- **ネットワーク制約（重大）**:
  - FargateタスクはUDPを直接受信するにはNLBが必要
  - NLBの固定費が高い（月額約$16〜）
  - `NET_ADMIN` capability が必要 → Fargate では**制限あり**
  - WireGuardのカーネルモジュールは使えない → **wireguard-go（ユーザー空間実装）が必要**で性能が劣化
- **Elastic IP**: NLBに紐付ける形で対応（直接割り当て不可）
- **起動時間**: コンテナの起動自体は速いが、NLBのヘルスチェック通過に時間がかかる
- **コスト**: NLBの固定費が大きなオーバーヘッド

#### コスト見積もり

| リソース | 仕様 | 月額（USD） |
|---------|------|------------|
| Fargate (0.25 vCPU, 0.5GB) | 1日8時間 × 30日 | ~$2.40 |
| NLB | 固定費 | ~$16.20 |
| Elastic IP | NLB用 | ~$3.65 |
| データ転送 | 100GB/月 | ~$11.40 |
| **合計** | | **~$34/月** |

### 3. ECS on EC2

#### 構成
- EC2インスタンス上でECSコンテナエージェントを実行
- WireGuardコンテナをホストネットワークモードで実行

#### メリット
- **カーネルアクセス**: ホストのWireGuardカーネルモジュールを利用可能
- **ネットワーク**: `--network host` でEC2のネットワークを直接使用 → NLB不要
- **コンテナの利点**: デプロイの再現性、ロールバックの容易さ
- **Elastic IP**: EC2に直接割り当て可能

#### デメリット
- **EC2管理が必要**: Fargateのサーバーレスの利点がない
- **複雑さ増大**: EC2 + ECS Agent + コンテナの3レイヤー管理
- **オーバーヘッド**: ECS Agentがリソースを消費
- **コスト**: EC2単体と同じ + ECS管理の複雑さ

#### コスト見積もり

EC2単体とほぼ同じ（~$17/月）だが、運用の複雑さに対するメリットが薄い。

### 4. Lightsail（参考）

#### 構成
- Lightsailインスタンス（最小$3.50/月）
- 固定IPアドレス付き

#### メリット
- **シンプルな料金体系**: 月額固定
- **固定IP無料**: インスタンスに紐付いている間は無料
- **データ転送込み**: 月間転送量が含まれる（1TB〜）

#### デメリット
- **常時起動前提**: 停止しても月額課金が発生
- **Terraform対応**: 対応しているが、EC2ほどの柔軟性はない
- **スケーリング**: 手動でのサイズ変更のみ
- **将来の拡張性**: EC2と比較して機能が限定的

#### コスト見積もり

| プラン | スペック | 月額（USD） |
|-------|---------|------------|
| nano | 0.25GB RAM, 2vCPU | $3.50 |
| micro | 0.5GB RAM, 2vCPU | $5.00 |
| small | 1GB RAM, 2vCPU | $10.00 |

## 推奨

### 結論: EC2 を採用

**理由:**

1. **WireGuardとの相性が最良**: カーネルモジュールを直接利用でき、最大限の性能を発揮
2. **コスト最適化**: 停止時はEBS/EIP費用のみ。オンデマンド起動でコストを最小化
3. **シンプル**: VPN構築に最も適した環境。情報量も豊富
4. **Elastic IP**: 固定IPを直接割り当て可能で、iPhone側の接続先設定が変わらない
5. **起動/停止**: CLI1コマンドで即座に制御可能

### ECS Fargateを採用しない理由

ECSは興味深い選択肢だが、VPNサーバーとしては以下の致命的な問題がある：

- **`NET_ADMIN` capability**: WireGuardのtunデバイス操作に必要だが、Fargateでの制限がある
- **カーネルモジュール不可**: wireguard-goへのフォールバックで性能が30〜50%劣化
- **NLBコスト**: 月額$16の固定費がEC2構成の全コストに匹敵
- **複雑さ**: VPNのためだけにコンテナオーケストレーションは過剰

### 推奨インスタンスタイプ

| ユースケース | インスタンス | vCPU | メモリ | 理由 |
|-------------|------------|------|--------|------|
| 同時接続5人以下 | t3.nano | 2 | 0.5GB | WireGuardは軽量。個人利用なら十分 |
| 同時接続6〜20人 | t3.micro | 2 | 1GB | バースト対応あり。20人同時でも問題なし |
| ピーク時 | t3.small | 2 | 2GB | 余裕を持った構成。通常は不要 |

**初期推奨: t3.nano で開始し、必要に応じてインスタンスタイプを変更**

インスタンスタイプの変更はEC2停止→タイプ変更→起動で可能。Terraformで管理していれば変数1つの変更で対応できる。

### EIP運用方針: 都度作成/削除 + サブドメイン

> 調査日: 2026-03-25

#### 背景

EIPはEC2停止中も $0.005/時間（月額$3.65）が課金される。VPNを全く使わない月もあるため、使用時のみEIPを作成しコストを削減したい。

#### EIP都度作成/削除の影響調査

| 観点 | 影響 |
|------|------|
| IPアドレス | 毎回異なるIPが割り当てられる（同一IPの保証なし） |
| WireGuardクライアント | Endpoint直書き(IP)の場合、全クライアントの設定変更が必要 |
| セキュリティグループ | 影響なし（SGはENIに紐付くため） |
| AWS API制限 | 1日数回の操作では全く問題なし |
| Terraform | EIPをTerraform管理外にする必要あり（stateとの不整合が発生するため） |

#### 回避策: サブドメイン + DNS自動更新

WireGuardはEndpointに**FQDN（ドメイン名）を指定可能**。既存ドメインのサブドメインを利用することで、IPが変わっても問題ない。

```ini
# クライアント設定（IP直書きではなくドメイン名を使用）
[Peer]
Endpoint = vpn.example.com:51820
```

#### AWSアカウント構成とサブドメイン委譲

既存ドメインは別のAWSアカウント（親アカウント）で管理しているため、AWS Organizationsのクロスアカウントでサブドメインを委譲する。

```
AWS Organization
├── 親アカウント (既存・ドメイン管理)
│   └── Route53 Hosted Zone: example.com
│       └── NS レコード追加: vpn.example.com → VPNアカウントのNSを指定
│
└── VPNアカウント (本プロジェクト用・新規作成)
    └── Route53 Hosted Zone: vpn.example.com
        └── A レコード: vpn.example.com → EIP (起動時に動的更新)
```

**委譲手順:**
1. VPNアカウントで `vpn.example.com` のホストゾーンを作成
2. 作成されたNSレコード（4つのネームサーバー）を取得
3. 親アカウントの `example.com` ホストゾーンにNSレコードを追加（`vpn.example.com` → VPNアカウントのNS）
4. 以降、`vpn.example.com` のDNS管理はVPNアカウント側で完結

#### 起動/停止フロー

```
起動: EC2起動 → EIP作成 → EC2にアタッチ → Route53 Aレコード更新 → WireGuard自動起動
停止: EC2停止 → EIP解放
```

#### コスト比較

| 方式 | 月額 (使用0h) | 月額 (使用60h) | 月額 (使用240h) |
|------|-------------|---------------|----------------|
| EIP保持 | $3.65 | $3.65 | $3.65 |
| EIP都度作成/削除 | $0 | $0.30 | $1.20 |
| Route53 Hosted Zone | $0.50 | $0.50 | $0.50 |
| **都度方式の実質コスト** | **$0.50** | **$0.80** | **$1.70** |
| **保持方式との差額** | **-$3.15** | **-$2.85** | **-$1.95** |

**全く使わない月は$3.15の節約**。既存ドメインのサブドメイン利用でRoute53ホストゾーン($0.50)のみの追加コスト。

#### 決定事項

- **EIPは都度作成/削除する**（コスト最適化）
- **サブドメインをEndpointに使用**（IP変動の影響を吸収）
- **クロスアカウントでサブドメイン委譲**（親アカウント → VPNアカウント）
- **EIPはTerraform管理外**とし、起動/停止スクリプトで管理
- **Route53ホストゾーンはTerraformで管理**（一度作成したら変更しないため）

### 補足: 将来のECS移行パス

EC2で運用を開始し、将来的にAdmin管理コンソールやユーザー管理機能を追加する際に、ECS (on EC2, ホストネットワークモード) への移行を検討する。これにより：
- VPNサーバーのコンテナ化による再現性向上
- 管理APIサーバーとVPNサーバーの同一EC2上での共存
- デプロイの自動化
